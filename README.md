# CodeBreakers

A small full-stack code-breaking game built with **JavaScript, PHP, MongoDB and Docker**.

The goal of this project is to practice full-stack development, HTTP communication, REST API design, database operations and Docker containerization by building a simple but complete game.

## Game Overview

CodeBreakers is a number-guessing game.

The player enters a username and starts a game. The server generates a secret 4-digit code, and the player must guess it before running out of attempts.

After each guess, the game displays feedback and updates the remaining attempts.

When the game finishes, the player's score is calculated and saved in MongoDB.

### Game Flow

1. The player opens the application.
2. The first page displays the global leaderboard.
3. The leaderboard shows the top 5 or 10 players, ranked by their best score.
4. The player enters a username.
5. The player starts a new game.
6. The server generates a secret code.
7. The player submits guesses until they crack the code or run out of attempts.
8. Each guess is displayed on the screen, together with the number of attempts used and remaining.
9. When the game ends, the final score is calculated.
10. The score and game result are saved in MongoDB.
11. The player can return to the leaderboard.

## Game Rules

- The secret code contains 4 digits.
- Each digit is between 0 and 9.
- The code is generated by the backend (PHP).
- The player has a maximum of 8 attempts.
- Each guess must contain exactly 4 digits.
- After each guess, the game provides feedback:
  - Correct digit in the correct position.
  - Correct digit in the wrong position.
  - Incorrect digit.
- The game ends when:
  - The player guesses the secret code.
  - The player runs out of attempts.

### Scoring System

The final score is calculated using:

- Number of attempts used.
- Time taken to complete the game.
- Whether the player successfully cracked the code.

The scoring formula will be implemented in PHP so that the backend controls the final score.

The exact scoring formula can be adjusted during development.

## Leaderboard

The landing page displays the global leaderboard.

Each leaderboard entry contains:

- Player username.
- Score.
- Attempts used.
- Time taken.

Players are ranked by score, from highest to lowest.

Only the top 5 or 10 results are displayed.

## Architecture

The application follows a simple client-server architecture.

```text
              PLAYER
                |
                v
       +------------------+
       |     FRONTEND     |
       |                  |
       | HTML / CSS / JS  |
       +------------------+
                |
                | HTTP Requests
                | Fetch API
                | JSON
                |
                v
       +------------------+
       |      PHP API     |
       |                  |
       | Game Logic       |
       | Score Calculation|
       | Validation       |
       +------------------+
                |
                | MongoDB Driver
                |
                v
       +------------------+
       |     MONGODB      |
       |                  |
       | Games            |
       | Scores           |
       +------------------+
```

The frontend communicates with PHP through HTTP requests.

PHP handles the game logic, validates player actions, calculates scores and communicates with MongoDB.

The frontend never communicates directly with MongoDB.

## API Endpoints

The backend exposes a small set of HTTP endpoints.

| Method | Endpoint                 | Description                         |
| ------ | ------------------------ | ----------------------------------- |
| GET    | `/api/leaderboard.php`   | Retrieve top 5 or 10 players        |
| POST   | `/api/games.php`         | Create a new game                   |
| GET    | `/api/games.php?id={id}` | Retrieve game information           |
| POST   | `/api/guess.php`         | Submit a guess and receive feedback |

### GET /api/leaderboard.php

Returns the global leaderboard.

Example response:

```json
{
  "players": [
    {
      "username": "Alex",
      "score": 1500,
      "attempts": 3,
      "time": 25
    },
    {
      "username": "Sarah",
      "score": 1200,
      "attempts": 4,
      "time": 32
    }
  ]
}
```

### POST /api/games.php

Creates a new game.

Example request:

```json
{
  "username": "Alex"
}
```

The backend generates the secret code, creates a game record and returns the game ID.

Example response:

```json
{
  "success": true,
  "gameId": "game_123",
  "attemptsRemaining": 8
}
```

### POST /api/guess.php

Submits a player's guess.

Example request:

```json
{
  "gameId": "game_123",
  "guess": [4, 2, 7, 9]
}
```

Example response:

```json
{
  "success": true,
  "correctPositions": 2,
  "correctDigits": 1,
  "attemptsUsed": 1,
  "attemptsRemaining": 7,
  "gameOver": false,
  "won": false
}
```

When the game ends, the backend calculates and saves the final score.

## MongoDB Data Model

For the initial version, only two collections are needed.

### games

Stores individual game sessions.

Example document:

```json
{
  "_id": "game_123",
  "username": "Alex",
  "secretCode": [4, 8, 2, 9],
  "attemptsUsed": 3,
  "attemptsRemaining": 5,
  "guesses": [
    [4, 2, 7, 9],
    [4, 8, 3, 5],
    [4, 8, 2, 9]
  ],
  "startedAt": "2026-10-30T15:00:00Z",
  "finishedAt": "2026-10-30T15:00:25Z",
  "durationSeconds": 25,
  "won": true,
  "score": 1500
}
```

### scores

Stores completed game results used by the leaderboard.

Example document:

```json
{
  "username": "Alex",
  "score": 1500,
  "attempts": 3,
  "time": 25,
  "won": true,
  "createdAt": "2026-10-30T15:00:25Z"
}
```

Each completed game creates a score record.

The leaderboard queries this collection, sorts by score descending and returns the top results.

## Docker

The application will run using Docker Compose.

The initial setup will include:

- PHP container: Runs the application and API.
- MongoDB container: Stores game sessions and scores.

MongoDB connection details will be provided to PHP through environment variables.

Example:

```env
MONGO_URL=mongodb://mongo:27017/codebreakers
```

The PHP application will retrieve the connection URL using:

```php
$mongoUrl = getenv('MONGO_URL');
```
